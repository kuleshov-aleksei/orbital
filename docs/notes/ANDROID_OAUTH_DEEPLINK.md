# Android app: OAuth via deep link (deferred)

Status: **not implemented**. QR device linking (`handlers/qrloginhandler.go`) is the
supported way to sign in on the Android app until this is done.

## Why the Electron flow doesn't carry over

Electron signs in through a loopback server: the backend's Electron callback
(`authhandler.go`, the electron branch of the OAuth callback) redirects to
`http://127.0.0.1:27271/callback?token=…&expires=…&state=…`, served by
`electron/main/features/oauth.ts`. A phone has no such listener.

## Plan

1. **Client kind in the OAuth state.** `AuthService.GenerateState(provider, isElectron bool)`
   becomes a client kind (`web` / `electron` / `android`). `/auth/{provider}/url?client=android`
   reuses the Electron OAuth client registration (same provider redirect URI);
   only the final hop differs.
2. **One-time code, not the JWT, in the deep link.** Another app can register
   the `orbital://` scheme and receive the redirect, so the backend redirects to
   `orbital://auth/callback?code=…&state=…`, where `code` is single-use with a short TTL (~60 s)
   and is stored server-side next to the state. The app exchanges it with
   `POST /api/auth/exchange {code, state}` → `AuthResponse`. Tie the code to a PKCE-style
   verifier generated by the app (sent with `/url`, proven at `/exchange`) so an intercepted
   code is useless on its own.
3. **Android side.**
   - `AndroidManifest.xml`: an `intent-filter` (VIEW, DEFAULT, BROWSABLE) with `android:scheme="orbital"`, `android:host="auth"` on `MainActivity` (already `singleTask`).
   - Open the provider URL with `@capacitor/browser` (Custom Tab) via `platform.openExternal`.
   - `App.addListener("appUrlOpen")` → check `state`, call `/auth/exchange`, `Browser.close()`,
     then the same path as Electron's `onOAuthToken` in `App.vue`.
   - Fold `api.ts` `initiateOAuthLogin`'s `isElectron()` branch into `services/platform.ts`.
4. **Tests.** Backend: the code is single-use, expires, and fails with a wrong state or verifier.
   The Electron callback is unchanged.

Optional later: verified App Links (`https://<domain>/.well-known/assetlinks.json`)
instead of a custom scheme. This removes the interception risk, but needs the release signing key's fingerprint.
